# Alice xAI/SuperGrok OAuth 接入修订计划

## 总结
OAuth 生命周期独立、HTTP 调用前解析 Authorization, 以xAI 为 OAuth 首个支持, 用户可以接入其他OAuth

保留原方案“OAuth 生命周期独立、HTTP 调用前解析 Authorization”的核心方向，但修正以下问题：

- xAI OAuth 的 LLM 通道使用 Responses API；不能假设继续走现有 `/chat/completions`。
- 认证与协议分离：preset 显式保存 `protocol + credentialId`。
- OAuth 上下文升级为统一 Credential 上下文，同时管理 API Key 与 OAuth。
- 首版覆盖 Chat/Talk/Memorize、Pi/SubAgent 和 xAI 图片。
- OAuth token 只能发送到 `https://api.x.ai`，禁止跟随任意 preset Base URL，避免凭据泄漏。
- 不增加任何 prompt、隐藏消息或 layer 顺序变化；Preview 必须展示实际协议请求。

## 核心接口与存储

- LLM preset 升级为 schema v2：

  ```ts
  type LLMProtocol =
    | "openai-chat-completions"
    | "openai-responses";

  type LLMApiPreset = {
    name: string;
    protocol: LLMProtocol;
    credentialId: string;
    baseURL: string;
    model: string;
    // 其余采样、流式、能力字段保持
  };
  ```

- 凭据公开记录只包含 `id、label、kind、provider、status、accountLabel、时间`；API Key、access token、refresh token 等进入加密 payload，任何 Admin 响应和日志都不返回秘密。
- 新增独立 `memory-files/credentials.sqlite`，使用 AES-256-GCM、随机 IV、带 credential 元数据的 AAD。主密钥为 `.env` 中的 `ALICE_CREDENTIAL_MASTER_KEY`。
- 部署迁移时一次性生成 32 字节随机主密钥并写入 `.env`；迁移实现不进入业务代码库，完成后删除。业务启动只读取该值，缺失时明确失败，不执行生成或迁移。`.env.example` 只记录变量说明。
- 引入维护成熟的 `openid-client`，通过 `https://auth.x.ai/.well-known/openid-configuration` discovery 执行 Device Authorization Grant、refresh、userinfo 和 revoke，不手写 OAuth 协议解析。
- xAI 使用已确认接受风险的共享 public client ID；请求 scopes 固定为 `openid profile email offline_access grok-cli:access api:access`，但启动授权前必须验证 discovery 声明仍支持 device grant、refresh grant 和全部 scopes，否则明确失败。
- 通用认证端口：

  ```ts
  interface RequestAuthorization {
    authorization(target: URL): Promise<string>;
    retryAfterUnauthorized(input: {
      target: URL;
      rejectedAuthorization: string;
    }): Promise<string | undefined>;
  }
  ```

  API Key 的 `retryAfterUnauthorized` 返回 `undefined`；OAuth 使用 credentialId 级 single-flight 刷新，并比较被拒 token，避免并发请求重复轮换 refresh token。

## 实现改动

- Credential/OAuth：
  - Device login session 只保存在进程内，状态为 `pending | connected | expired | failed`；后台负责按服务端 interval 轮询，Admin 轮询只读状态。
  - access token 到期前 120 秒刷新；完整 token set 原子加密落盘，服务端未返回新 refresh token 时保留旧值。
  - `invalid_grant`、撤销或确定性 4xx 将凭据标记为 `reconnect_required`，清除不可再用的 token，不回退 API Key。
  - xAI credential 的授权方法校验目标 origin 必须为 `https://api.x.ai`；图片和 LLM 都不能覆盖该限制。
  - 删除仍被 preset 或照片配置引用的凭据返回 `409` 和引用位置。断开连接先完成远端 revoke；失败时保留本地凭据并返回 JSON 错误。

- Preset 与迁移：
  - 合并当前 Admin/runtime 两套 `LLMApiPreset` 定义和 normalize 逻辑，统一从一个 credential-aware preset store 读取。
  - 部署时通过一次性独立脚本执行 schema v1→v2 迁移：每个旧 named preset 的 `apiKey` 创建确定性 API Key credential，preset 写入 `credentialId` 并删除明文；迁移完成并验证后删除迁移实现，业务启动路径禁止包含或调用一次性迁移逻辑。
  - 旧 `selfieXaiImageApiKey` 同样迁入 credential store，照片配置改为 `selfieXaiCredentialId`；其他 OpenAI/relay 图片密钥、TTS/ASR 密钥和非 preset 的环境配置不在本次迁移范围。
  - 跨 JSON/SQLite 迁移使用 journal、确定性 upsert 和临时文件原子替换；中途失败时旧配置仍可重试。保存加密的迁移快照并提供显式 rollback 脚本，不保留明文备份。
  - 迁移完成后不再读取旧 `apiKey` 字段作为运行时 fallback；残留或畸形 schema 明确报错。

- LLM 与 Preview：
  - `createLLMClientFromPreset` 根据 `protocol` 选择现有 Chat Completions client 或新增 Responses client，两者都接收解析后的 `RequestAuthorization`。
  - Responses client 将现有 `LLMMessage/LLMToolSpec` 映射为 Responses `input/function_call/function_call_output/tools`，并把普通响应及 SSE 事件重新归一化为现有 `LLMChatResult`、reasoning delta、tool-call delta 和 usage。
  - text 与 image input 首版支持；未验证的 Responses audio input 明确拒绝，不转换成其他形式。
  - `extraParams` 继续由 preset 控制，但协议保留字段由 client 最终覆盖；Responses 使用 `max_output_tokens`，不注入 Chat 专属 `stream_options`。
  - 把 raw request builder 改为协议感知，Prompt Preview、LLM Request 和实际请求展示同一最终 wire shape；不改变消息、prompt 内容或 layer 顺序。
  - observability seam 同时识别 `/chat/completions` 和 `/responses`，解析 Responses 的模型、finish reason、usage 与缓存 token。

- 请求、Pi 与图片：
  - `llm-upstream-requester` 只依赖 `RequestAuthorization`，不知道 OAuthService、provider 或 credentialId。
  - 单次逻辑请求拥有独立预算：最多一次 502/503 重试、最多一次 OAuth 401 刷新重放，总网络请求不超过三次；API Key 的 401 不重试。外部 AbortSignal 立即停止刷新等待和重试。
  - Pi preset snapshot 保存 `protocol + credentialId`，不保存任何上游秘密；宿主 relay 动态解析凭据，sandbox 仍只持有 relay capability token。
  - Pi worker 根据 preset 注册 `openai-completions` 或已现场确认支持的 `openai-responses`；relay 分别开放对应路径并同协议转发，不实现两种协议之间的翻译。
  - Pi relay 继续由 preset 决定 model、stream、采样参数；Pi 的 messages/input、tools、tool choice 按对应协议透传，保持现有 tool-loop 语义。
  - xAI 图片 provider 接收同一 `RequestAuthorization`，继续调用 `/images/edits` 并保留现有图片参数、代理、超时和文件处理；OAuth 401 只刷新重放一次。
  - Admin 增加 credential 管理、xAI Device Code 连接状态和 reconnect/disconnect；LLM preset 与照片 xAI 配置使用 credential 下拉选择。所有路由位于 `/admin/api/...`，继续受现有 Admin 网络授权边界保护。

## 测试与验收

- OAuth：discovery 校验、device pending/slow_down/成功/超时、userinfo、提前刷新、refresh token 轮换、并发 single-flight、`invalid_grant`、revoke 和 reconnect。
- 安全：错误主密钥、密文/AAD 篡改、公开响应脱敏、日志无 token、xAI token 向非 `api.x.ai` 发送时失败、数据库及目录权限。
- 迁移验收：全部 preset 与照片 xAI key 已写入凭据库，配置已升级到 v2，旧字段不再生效；保留加密快照并验证独立 rollback 工具。
- LLM：现有 Chat Completions 回归；Responses 的文本、图片、reasoning、工具调用、多轮 tool result、非流式、流式、usage 与错误响应。
- Preview：Chat 和 Responses 的 raw request 分别与实际发送 body 一致，且 prompt 消息序列和 layer 顺序不变。
- 重试：401→刷新成功、401→刷新失败、502→成功、401/502 组合、AbortSignal、API Key 401 不重放。
- Pi：两种 protocol 注册、Responses relay 流式工具调用、能力 token 隔离、credential 刷新无需轮换 sandbox token、取消和并发槽释放。
- 图片：API Key 与 OAuth 成功路径、OAuth 401 重放、缺失/失效 credential、图片结果写入。
- Admin：输入校验均返回 JSON 错误；引用中凭据删除返回 409；API 响应不泄露秘密。
- 完成后运行 `npm run typecheck`、相关定向测试和完整 `npm test`，并按源码实际行为更新中文 `project_summary.md`。

验收标准：SuperGrok 完成一次 Device Code 登录后，同一 credential 可用于主 LLM、Pi/SubAgent 与 xAI 图片；进程重启后可自动刷新；现有 API Key preset 迁移后行为不变；任何 OAuth/API Key 失败均明确报错且不存在静默 fallback。

## 已锁定假设

- 接受复用 xAI 共享 public client ID 的授权边界和未来失效风险；实现不冒充 client secret。
- xAI OAuth 首版只允许 `openai-responses` 和全球 `https://api.x.ai/v1`。
- Base URL、协议和 credential 是独立配置，但 xAI OAuth 的 provider policy 会校验合法组合。
- `.env` 与加密 credential 数据库必须共同备份；丢失主密钥不会尝试绕过解密。
- 不新增 prompt，不修改 tool 暴露规则，不引入兼容性 fallback。

# Time Conflex Debug Log

UTC time: 2026-06-02T16:58:55Z

## Background

The message/toolcall path was returning local wall-clock strings from several independent call sites. The desired rule is:

1. Capture the source instant as UTC first.
2. Store the UTC value in a `*_utc` / `*Utc` field when the record supports it.
3. Derive configured-timezone display fields from that UTC source.

## Audit Summary

Risky direct time usage was concentrated in:

- Messaging send failure paths that updated message status with only local time.
- Feishu lifecycle event normalization, where read/recall/reaction events did not carry UTC.
- File log daily bucketing, which used the local `time` string instead of the UTC source.
- Sleep cocoon state/output timestamps, which only carried local time.
- Media selfie prompt daily shell variables, where `date` used a UTC ISO date.
- Daily shell fallback parsing, which parsed no-zone local strings with `new Date`.

Low-risk direct time usage remains for IDs, timeouts, retry delays, TTL cleanup, elapsed-time metrics, cache busting, and test fixtures.

## Changes Made

- `packages/storage/src/file-log-store.ts`
  - File log daily path now uses `utcTime ?? time` as the source before converting to the configured timezone.

- `packages/storage/src/sqlite-store.ts`
  - `markOutboundMessageFailed`, `markMessageRead`, `markMessageRecalled`, and `updateMessageReaction` now accept optional UTC inputs.
  - When UTC is provided, local fields are derived from UTC using the store timezone instead of re-parsing a local string.

- `plugins/feishu/src/types.ts`
  - Feishu lifecycle events now support `occurredAtUtc`.

- `plugins/feishu/src/handlers/lifecycle.ts`
  - Lifecycle event time normalization now returns both `occurredAt` and `occurredAtUtc`.
  - Numeric timestamps are treated as UTC source instants first.

- `apps/api/src/message-runtime.ts`
  - Lifecycle read/recall/reaction updates pass UTC through to storage.
  - Outbound send-failure paths capture one `time.now()` sample and pass both local and UTC values.
  - Recovered/manual generated events now carry `receivedAtUtc` when available.

- `apps/api/src/index.ts`
  - System notice send-failure path now passes UTC to storage.
  - Prompt preview and generated sleep cocoon events now include `receivedAtUtc`.

- `apps/api/src/admin-routes.ts`
  - Admin prompt/tool preview events now include `receivedAtUtc`.
  - Feishu test sends now include `createdAtUtc`.

- `plugins/sleep-cocoon/src/index.ts`
  - Sleep cocoon state now records `sleepCocoonEnteredAtUtc`.
  - Sleep cocoon notice output now includes `createdAtUtc`.

- `plugins/shell/src/index.ts`, `plugins/media/src/index.ts`, `plugins/messaging/src/index.ts`, `plugins/bookcase/src/index.ts`
  - Direct outbound send-failure updates now pass UTC to storage.

- `plugins/media/src/index.ts`
  - Selfie prompt `dailyShellRaw.date` is now configured-timezone local date.
  - Added `dateUtc` and `createdAtUtc` alongside local fields.

- `core/agent/src/shells.ts`
  - Daily shell fallback expiry parsing now uses `parseZonedIso(createdAt, timeZone)` instead of `new Date(createdAt)`.

## Remaining Notes

- Memory diary fallback still has no local time provider in `MemoryWriteOptions`; normal callers pass `windowEndAt` / `now`, but the bare fallback cannot know the configured timezone.
- Token usage and several admin/session bookkeeping timestamps remain local-only because their storage schema does not currently have UTC mirror columns.
